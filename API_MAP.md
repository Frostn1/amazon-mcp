# Amazon search & suggestions — endpoint map

Probed 2026-11-04 with plain `curl` (desktop Chrome User-Agent, no cookies, no login).
Everything below returned 200 without a CAPTCHA at low volume.

## 1. Suggestions (autocomplete) — clean JSON

```
GET https://completion.amazon.com/api/2017/suggestions
```

| param | example | meaning |
|---|---|---|
| `prefix` | `iphone 16 c` | what the user has typed (required) |
| `alias` | `aps` | search department: `aps` = All, `electronics`, `stripbooks`, … (same values as the search dropdown) |
| `mid` | `ATVPDKIKX0DER` | marketplace id (US). UK = `A1F83G8C2ARO7P` on `completion.amazon.co.uk` |
| `limit` | `11` | max suggestions |
| `suggestion-type` | `KEYWORD`, `WIDGET` | repeatable; `WIDGET` adds rich widgets |
| `last-prefix`, `event`, `avg-ks-time`, `site-variant`, `client-info`, `lop` | | telemetry; optional |

Response:
```json
{
  "alias": "aps", "prefix": "s", "suffix": "",
  "suggestions": [
    { "type": "KEYWORD", "value": "switch 2", "refTag": "nb_sb_ss_..._2_1",
      "strategyId": "p13n-expert-pd-ops-ranker",
      "complementaryInfo": { "THUMBNAIL_IMAGE": { "value": "https://m.media-amazon.com/..." } } }
  ],
  "predictiveText": ..., "responseId": "...", "shuffled": false
}
```
Use `refTag` as `ref=` on the follow-up search if you want to look like a suggestion click.

## 2. Search results page — HTML

```
GET https://www.amazon.com/s?k=<query>[&i=<alias>][&rh=<filters>][&s=<sort>][&page=N]
```

Params seen in your URL:

| param | value | meaning |
|---|---|---|
| `k` | `s` | the query |
| `crid` | `FILZA5J09IXZ` | search-session id generated by the search box; optional |
| `sprefix` | `s,aps,234` | `<typed prefix>,<alias>,<suggest latency ms>`; telemetry, optional |
| `ref` | `nb_sb_noss_2` | nav-bar search box, *no suggestion* used; optional |

Other useful params:
- `i=<alias>` — restrict to a department (`electronics`, …).
- `rh=` — filters, comma-joined `key:value` (URL-encoded `%3A`): `n:<nodeId>` category, `p_72:1248915011` 4★+, `p_76:1249155011` Prime, `p_36:<min>-<max>` price in cents, `p_89:<Brand>` brand. Exact ids come from the refinement links on the page (`href="/s?k=...&rh=..."`), ~230 per page.
- `s=` sort: `price-asc-rank`, `price-desc-rank`, `review-rank`, `date-desc-rank`, `exact-aware-popularity-rank`.
- `page=N` — ~20–22 organic results per page; total in `"N results for"`.

Parsing: each result is
`<div role="listitem" data-asin="B0…" data-index="3" data-component-type="s-search-result">`.
Inside: title in `h2`, price in `.a-price .a-offscreen` (or `.a-price-whole`), rating in
`.a-icon-alt` (`"4.6 out of 5 stars"`), image `img.s-image`. Ads carry `AdHolder` class / "Sponsored".

## 3. Search results AJAX stream — the SPA's own endpoint (best for agents)

```
POST https://www.amazon.com/s/query?k=<query>&page=N[&rh=…&s=…]
Content-Type: application/json
X-Requested-With: XMLHttpRequest
body: {"customer-action":"pagination"}
```
Same params as `/s`. Response (gzip — use `--compressed`) is chunks separated by `&&&`, each a JSON array:
```json
["dispatch", "data-main-slot:search-result-3",
 {"asin": "B0C2QF44J5", "index": 3, "html": "<div role=\"listitem\" ...>"}]
```
So you get ASIN + index as JSON for free and only parse the card HTML for title/price/rating. ~200 KB vs ~1.9 MB for the full page.

## 4. Product page

```
GET https://www.amazon.com/dp/<ASIN>
```
Title `#productTitle`, price `#corePrice_feature_div .a-offscreen`, bullets `#feature-bullets`. ~490 KB.

## 5. Cart

- **Add:** `POST /cart/add-to-cart/ref=dp_start-bbf_1_glance`, form-encoded.
  - Send every `<input>` from the product page's `form#addToCart`. That includes `anti-csrftoken-a2z`, `offerListingID`, `ASIN`, `merchantID` and `items[0.base][quantity]`.
  - Leave out `submit.buy-now`.
  - Needs the same cookie jar as the product page fetch. Returns 200 with an "Added to cart" page.
- **View:** `GET /gp/cart/view.html`. Each item row is `[data-asin][data-itemid][data-itemtype=active]`. Rows carry `data-price`, `data-quantity` and `data-producttitle`. The subtotal is in `#sc-subtotal-amount-buybox`.
- **Remove:** `POST` to the action of `form#activeCartViewForm`, with all of its hidden inputs (including the CSRF token) plus `submit.delete-active.<itemid>=Delete`.
- **Signed-in cart:** the same three calls work on the user's own cart when the jar carries account cookies (`at-main`, `sess-at-main`, `x-main`). Signed-out pages show `Hello, sign in` in `#nav-link-accountList-nav-line-1`.
- *Not usable:* `/gp/aws/cart/add.html?ASIN.1=…` (the old Associates "add to cart form") now dead-ends in a sign-in/claim flow without an Associates tag.

## Caveats
- Amazon's Conditions of Use prohibit automated data extraction; this is fine for research/personal agents at human-ish rates, not for bulk scraping.
- Bot defenses: higher volume → `/errors/validateCaptcha` page or 503. Keep a session cookie jar (`session-id`, `i18n-prefs`), real UA, `Accept-Language`, and throttle.
- Prices/availability depend on delivery location (cookie-based, unset = default US ZIP).
- Sanctioned alternative: Product Advertising API (requires an Associates account with qualifying sales).
